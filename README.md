# Neovim config

One concern per file, grouped by what it is for. Adding a plugin, a keymap, an
autocommand or a whole feature never means editing an existing file's guts —
drop a file in the right directory and it is picked up.

`init.lua` is the only file with an order in it: it loads the four `config/`
modules, then the features, then the settings panel (which applies your saved
choices on top of everything else). Start there.

## Map

```
init.lua                table of contents — load order and nothing else
setup.sh                installs the dependencies on a new machine (see below)
CHEATSHEET.md           every keybinding, by area
lazy-lock.json          pinned plugin revisions — keep this file

bin/                    helper scripts this config shells out to
  livehtml              HTML live server + SSE reload (python3, no deps)
  mdpreview             chrome-less browser window (qutebrowser → firefox)
  texbuild              multi-pass LaTeX wrapper, used when latexmk is absent

lua/config/             how the editor behaves
  options.lua           options, one block per concern
  lazy.lua              lazy.nvim bootstrap, loads lua/plugins/*
  keymaps.lua           every keymap this config adds
  autocmds.lua          every autocommand, in augroups General / Prose / LSP
  bin.lua               finds bin/* (or the PATH equivalent)
  health.lua            :checkhealth config — is this machine set up?

lua/features/           functionality written for this config
  settings.lua          the :Settings panel (<leader>uS) — all the toggles
  templates.lua         new-from-template (<leader>nt)
  theme_picker.lua      <leader>th, and restoring that pick on startup
  preview/live.lua      autosync .tex/.typ to disk so previews update without :w
  preview/typst.lua     typst watch + PDF viewer
  preview/html.lua      HTML live server, auto-reload, index.html first

lua/dashboard/          dashboard art.lua + theme/compact.lua (path the plugin wants)
lua/plugins/            lazy.nvim specs, one file per area
colors/matugen.lua      the matugen colourscheme (loads lua/matugen.lua)
plugin/                 rtp plugins, auto-loaded before lua/
```

## Adding things

| I want to add… | do this |
| --- | --- |
| a **plugin** | create `lua/plugins/<area>.lua` returning a lazy.nvim spec. One file per area; nothing to register. |
| a **keymap** | `lua/config/keymaps.lua`, in the section for its prefix. |
| an **autocommand** | `lua/config/autocmds.lua`, in the augroup it belongs to — or next to the plugin it is about. |
| a **feature** | `lua/features/<name>.lua` returning a module; call `require("features.<name>").setup()` from `init.lua` only if it needs setting up. |
| a **toggle** in the settings panel | add a row to `schema` in `lua/features/settings.lua` and wire the effect in its `M.apply()`. The panel, the JSON persistence and `R` (reset) are automatic. |
| a **helper script** | put it in `bin/`, call it as `require("config.bin").path("name")`, and add its name to `SCRIPTS` in `setup.sh`. |
| a **snippet** | `snippets/<lang>.lua` — see `snippets/README.md`. |

## Reproducing on another machine

```sh
# copy or clone the config first, e.g.
#   git clone <your-remote> ~/.config/nvim
cd ~/.config/nvim
./setup.sh
```

1. checks every tool the config shells out to (the table mirrors
   `:checkhealth config`) and installs what is missing — Arch names, with
   `apt`/`dnf` equivalents where they differ;
2. links `bin/*` into `~/.local/bin` so the previews also work from a shell;
3. restores the plugin revisions pinned in `lazy-lock.json`;
4. prints what is left to do by hand.

`./setup.sh --check` changes nothing and just reports. `--no-plugins` skips
step 3. After the first launch, Mason installs the language servers listed in
`lua/plugins/lsp.lua`, and treesitter downloads parsers as you open filetypes
(needs `gcc` + `curl`, which step 1 installs).

Keep `lazy-lock.json` with the config: `:Lazy restore` then reproduces the same
plugin revisions on any machine.

## State that lives outside the config

| what | where | written by |
| --- | --- | --- |
| settings panel choices | `stdpath("state")/settings.json` | `:Settings` |
| colourscheme pick | `stdpath("data")/theme` | `<leader>th` |
| dashboard art pick | `stdpath("state")/dashboard_art` | `a` on the dashboard, `:DashboardArt` |
| plugin revisions | `lazy-lock.json` (in the config) | `:Lazy` |
| LSP servers | `stdpath("data")/mason` | `:Mason` |

## Do not edit by hand

- `lua/matugen.lua` — written by `matugen` from the wallpaper (its template
  targets that path). `colors/matugen.lua` is the colourscheme that loads it.
- `plugin/20-keybind-arranger.lua` — generated by `keybinds-gen apply`.
- `nvim-pack-lock.json` — not used by this config (a leftover from an
  experiment with Neovim's built-in pack system); harmless either way.
